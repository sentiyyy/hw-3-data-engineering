# Домашнее задание — вариант 10 «Аналитик»

**Автор отчёта:** Автономова Ксения Витальевна  
**Тема:** RustFS/S3, потоковый MapReduce, DuckDB, анализ зарплат и регионов.

Проект собирает один воспроизводимый снимок вакансий, помещает его в бакет `hh-lake`, читает этот же объект из RustFS двумя независимыми способами, сверяет результаты и формирует PDF-отчёт из фактических запусков. В коде нет заранее вписанных «красивых» результатов профилирования: время, память, частоты и медианы берутся из запуска.

> **Важно для сдачи.** Если для ДЗ № 2 уже был собран датасет, лучше использовать его, чтобы сохранить согласованность с предыдущей работой. Если такого файла нет, можно собрать актуальную выборку через публичный API HeadHunter. Доступ к API иногда ограничивается капчей/лимитами; в таком случае используйте импорт файла.

## 1. Что реализовано

- RustFS в Docker Compose, консоль `http://localhost:9001`, S3 API `http://localhost:9000`.
- Создание бакета `hh-lake` и сохранение исходного NDJSON-объекта `raw/analyst/vacancies.jsonl`.
- Сбор вакансий по заголовкам `аналитик` и `analyst` либо импорт собственного файла из ДЗ № 2.
- Нормализация названий навыков, удаление повторов внутри вакансии и дедупликация вакансий по ID.
- Собственная реализация MapReduce: объект из S3 читается потоково, записи группируются в чанки, mapper считает навыки/пары/тройки, reducer объединяет счётчики.
- Три размера чанка по умолчанию: 100, 500 и 1000 записей. Результаты каждого размера сохраняются локально и в RustFS.
- Независимый расчёт в DuckDB SQL непосредственно по `s3://hh-lake/raw/analyst/vacancies.jsonl`.
- Точная проверка совпадения одиночных навыков, пар и троек.
- Зарплатный анализ: медианы одиночных навыков и комбинаций, сравнение пары/тройки с наиболее часто встречающимся одиночным навыком из этой комбинации.
- Региональный анализ трёх регионов с наибольшим количеством вакансий: зарплаты, навыки, пары и тройки.
- Профилирование с минимум тремя попытками: wall-clock time, пик RSS через `psutil`, пик Python-аллокаций через `tracemalloc`.
- Бонус: сравнение полной загрузки объекта в память с потоковым MapReduce.
- PDF-отчёт генерируется из измеренных артефактов и содержит таблицы, проверку, профилирование, интерпретацию и место для реальных скриншотов RustFS.
- Юнит-тесты на нормализацию, фильтрацию, комбинации, независимость от размера чанка, формирование отчёта и fail-fast поведение при искусственном отказе mapper.

## 2. Быстрый запуск в Windows

Нужно установить и запустить **Docker Desktop** (с включённым WSL 2). В PowerShell перейдите в папку проекта.

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и при необходимости измените `RUSTFS_ACCESS_KEY` и `RUSTFS_SECRET_KEY`. Порты опубликованы только на `127.0.0.1`; не открывайте их в интернет с учебными локальными ключами.

Запустите RustFS:

```powershell
docker compose up -d rustfs
```

Откройте `http://localhost:9001` и войдите с логином/паролем из `.env`.

### Вариант A — собрать актуальные вакансии из HeadHunter API

```powershell
docker compose run --rm pipeline all --limit 1200 --chunk-sizes 100,500,1000 --attempts 3
```

Сбор 1200 карточек может занять несколько минут, потому что для структурированных навыков запрашиваются подробности вакансий. Параметр `--limit` можно уменьшить для быстрой проверки, но для содержательного регионального анализа лучше оставить 1200 или использовать имеющийся датасет.

### Вариант B — использовать датасет из ДЗ № 2

Положите свой файл в папку `data/` проекта, например `data/vacancies.jsonl`. Поддерживаются `.jsonl`, `.ndjson`, `.json` и `.csv`. Для CSV желательно иметь столбцы `id`, `name`/`title`, `area`/`region`, `salary_from`, `salary_to`, `salary_currency` и `skills`/`key_skills`. Навыки могут быть списком, JSON-массивом в строке или строкой с разделителями `;`, `,`, `|`.

```powershell
docker compose run --rm pipeline import-file /app/data/vacancies.jsonl
docker compose run --rm pipeline run --chunk-sizes 100,500,1000 --attempts 3
```

Если у вас CSV, замените путь на `/app/data/имя_файла.csv`.

### Запуск тестов

```powershell
docker compose run --rm --entrypoint python pipeline -m pytest -q
```

Тестовый набор содержит искусственные примеры и используется **только для проверки кода**. Эти примеры не используются для фактического отчёта.

## 5. Правила подсчёта

- Вакансия входит в вариант, если её название содержит `аналитик` или `analyst` без учёта регистра.
- Навыки приводятся к нижнему регистру; повтор одного навыка в вакансии учитывается один раз.
- Пара и тройка — неупорядоченные комбинации. Для предотвращения повторов используется сортировка навыков и `itertools.combinations` в MapReduce, а в SQL — строгие условия `skill_1 < skill_2 < skill_3`.
- Частота навыка/пары/тройки — число вакансий, в которых встречается этот навык/набор навыков, а не число повторений в описании.
- Для зарплат берётся середина указанного диапазона; если есть только одна граница, используется она. Не смешиваются валюты: анализ учитывает RUB/RUR. Суммы с разными условиями gross/net не корректируются, это ограничение указано в отчёте.
- Для анализа влияния пары/тройки на зарплату базовым уровнем служит медиана наиболее часто встречающегося одиночного навыка из комбинации. Минимальная поддержка по умолчанию — 5 зарплатных наблюдений; её можно менять через `MIN_COMBO_SUPPORT` в `.env`.
- Три региона выбираются автоматически по количеству вакансий в собранном снимке, а не вручную по заранее известным результатам.

Для вакансии с `n` различными навыками число возможных пар равно `n(n−1)/2`, троек — `n(n−1)(n−2)/6`. Поэтому число всех встреч комбинаций растёт быстрее, чем число одиночных навыков.

## 6. Воспроизводимость и ограничения

- Оба способа читают один объект `s3://hh-lake/raw/analyst/vacancies.jsonl`.
- MapReduce использует потоковое чтение S3 и чанки; DuckDB использует `httpfs` и SQL-запросы к S3.
- Пайплайн завершится с ошибкой, если контрольные частоты не совпадут. В этом случае смотрите `artifacts/verification.json` и `artifacts/run.log`; отчёт сохранит диагностические сведения.
- Сбор данных из HH API зависит от доступности сервиса, капчи и ограничений запросов. Для полного воспроизведения можно использовать зафиксированный снимок из ДЗ № 2.
- Разница медиан не является доказательством причинного влияния навыка на зарплату: результат может зависеть от уровня должности, опыта, отрасли и региона.
